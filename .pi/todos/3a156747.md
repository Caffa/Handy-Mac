## Implementation Complete

### Changes Made

1. **`src-tauri/src/transcription_coordinator.rs`**:
   - Added `Arc<AtomicBool>` field `active_use` to `TranscriptionCoordinator` to track if Handy is in active use
   - Added `Stage::is_active()` helper method
   - Added `set_stage()` helper function that updates both `stage` and `active_use` flag atomically
   - Added `is_active_use()` public method for querying active use state
   - Updated `start()` and `stop()` functions to accept `&AtomicBool` parameter
   - All stage transitions now use `set_stage()` to keep `active_use` in sync

2. **`src-tauri/src/lib.rs`**:
   - Added new `--is-active-use` CLI flag that returns:
     - Exit code 0 (active use) if the coordinator is in Recording or Processing stage
     - Exit code 1 (idle) if coordinator is in Idle stage
   - Updated `--is-recording` to include better documentation about its scope (audio recording only)
   - Both flags now print detailed debugging info to stderr

3. **`scripts/build-reinstall.sh`**:
   - Changed from `--is-recording` to `--is-active-use` as the primary check
   - Added fallback to `--is-recording` for older versions that don't support `--is-active-use`
   - Improved messaging to clarify what "active use" means

### "Active Use" Definition

Active use now includes:
- **Recording**: User is speaking, audio being captured
- **Processing**: Transcription, post-processing, or router filing in progress

Always-on mode (mic stream open but NOT actively recording) is **NOT** considered active use and won't block the reinstall script.

### Testing

- Build succeeded with only unrelated warnings
- The new `--is-active-use` flag is available for scripts
- Legacy `--is-recording` flag remains available for backward compatibility
